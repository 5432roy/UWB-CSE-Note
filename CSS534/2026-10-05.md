## Shared Memory — Lecture 2: Programming Foundations

### Main idea

**Shared memory** lets workers communicate by reading and writing shared variables. Memory is the communication medium, so ordinary variable assignments can pass data between workers. This makes the transition from sequential programming relatively smooth.

### Processes and threads

| Worker type | How memory is shared |
| --- | --- |
| **Processes** | Separate processes have separate address spaces, but the operating system can map shared memory pages into each process. |
| **Threads** | Threads in the same process share its address space, although each thread has its own execution state and stack. |

In the slide, `x = 10` belongs to Process A, and `z = x` represents the child reading a value. A normal `fork()` gives the child an initial copy of ordinary process memory; later changes to an ordinary variable are not automatically shared. For ongoing communication, the processes need an explicitly shared region.

In Process B, the main thread and child thread can access the same shared `y`. If the main thread sets `y = 10` and synchronization ensures that this happens before the child reads it, `z = y` gives the child the value 10.

The **distributed shared memory** oval represents a system that makes memory on different machines appear shared. The question mark beside the remote fork highlights that another machine cannot simply read a local variable without supporting machinery to transfer data and maintain consistency.

### Benefits and difficulties

| Benefits shown on the slide | Difficulties shown on the slide |
| --- | --- |
| Familiar variable access gives a gentle learning curve. | Workers must synchronize access to shared data. |
| Data in local DRAM makes implementation relatively straightforward. | Maintaining memory consistency is difficult, especially across machines. |
| Shared memory can be fast within one machine. | Sharing across multiple machines introduces communication overhead. |

**Synchronization** coordinates when workers read or write. For example, two workers updating the same counter can overwrite each other's work without coordination. **Memory consistency** concerns the rules governing which writes other workers can observe and in what order.

**OpenMP** provides higher-level support for shared-memory parallel programming, reducing the need to manage threads directly. The programmer still needs to identify shared data and coordinate conflicting accesses.

### Clarification: `shmget()` and `shmat()` in C

`shmget()` returns an integer identifier, `shmat()` returns a pointer to an attached shared-memory segment.

```c
// Illustrative System V shared-memory fragment; error checks omitted.
int h = shmget(IPC_PRIVATE, sizeof(int), IPC_CREAT | 0600);
void *s = shmat(h, NULL, 0);
int *x = (int *)s;
*x = 10;
```

1. **`shmget()`** creates or finds a shared-memory segment. Here, `IPC_PRIVATE` requests a new segment, `sizeof(int)` requests enough bytes for one integer, and `0600` gives the owner read/write permissions. The returned `h` is the segment identifier, not a memory address.
2. **`shmat()`** attaches segment `h` to the calling process's address space. `NULL` lets the system choose the address, and flags `0` request the default read/write attachment. The returned `s` is the address where this process can access the segment.
3. **`void *`** means a pointer without a specified pointed-to type. Converting it to `int *` lets the program interpret that memory as an integer.
4. **`*x = 10`** writes 10 into the shared region. Another process attached to the same segment can access that same stored value, with appropriate synchronization. Its pointer address need not be identical.

The distinction is: **`h` identifies the shared region; `s` points to that region inside the current process.** This API shares memory on the same operating-system instance; it does not implement the slide's distributed shared memory across computers.

Real code must check `shmget()` for `-1` and `shmat()` for `(void *)-1`, synchronize access, detach with `shmdt()`, and arrange removal with `shmctl(..., IPC_RMID, ...)` when finished.

## Inter-Process Communication: Pipes and Sockets

**Pipes** allow different processes on the same computer to communicate.

**Sockets** allow processes on different computers to communicate over a network. They can also be used for communication between processes on the same computer.
