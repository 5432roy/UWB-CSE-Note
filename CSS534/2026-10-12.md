## Monte Carlo estimation

**Monte Carlo estimation** uses random samples to estimate a quantity. For a standard geometric estimate of $\pi$, the fraction of uniformly sampled points inside a circle estimates the ratio of the circle's area to the surrounding square's area.

### Methodology in the example

1. Read `niter`, the number of samples for each quadrant batch.
2. Call `srand( SEED )` once, using `#define SEED 35791246`, to initialize the pseudorandom sequence.
3. Run four batches with `quad` from `0` through `3`. Reset `count` to zero at the start of each batch.
4. For each sample, generate `x` and `y` using `( double )rand( ) / RAND_MAX`, giving coordinates in $[0,1]$.
5. Compute `radius = x * x + y * y`. Here, `radius` stores the squared distance from the origin. Increment `count` when `radius <= 1`.
6. Add `( double )count / niter` to `pi` after each batch.

Each batch estimates the area of a unit quarter circle, $\pi/4$. If $H_q$ is the hit count in batch $q$ and $N$ is `niter`, the final estimate is:

$$
\widehat{\pi}=\sum_{q=0}^{3}\frac{H_q}{N}
=\frac{H_0+H_1+H_2+H_3}{N}.
$$

**The program generates $4N$ points in total**, although its printed `# of trials` is `niter`. All four batches use nonnegative coordinates; they represent four equal quadrant contributions without explicitly changing coordinate signs. The generator continues its sequence across batches because it is seeded only once.

The computation loop is:

```cpp
  for ( int quad = 0; quad < 4; quad++ ) {
    // for each quadrant
    count = 0;
    for ( int i = 0; i < niter; i++ ) {
      x = ( double )rand( ) / RAND_MAX;
      y = ( double )rand( ) / RAND_MAX;
      radius =  x * x + y * y;
      if ( radius <= 1 ) count++;
    }
    pi += ( double )count / niter;
  }
```

Source: [University of Utah's Monte Carlo π example](https://math.utah.edu/~treiberg/M2160w10.html).

### Researched parallel methodology

The four batches can be assigned to different workers, or the samples within each batch can be divided among workers. Keep coordinates, squared distances, and hit counts private to each worker. Combine the results after the workers finish. For this program's $4N$ samples, the estimate is the combined hit count divided by $N$, equivalently four times the hit fraction over all $4N$ samples.

In an OpenMP implementation, a sum reduction combines the workers' counts. Each thread can keep its own random-number generator with a distinct seed to avoid concurrent access to shared generator state. Distinct seeds alone do not guarantee nonoverlapping random sequences.

Source: [Michael Zingale's OpenMP Monte Carlo π example](https://zingale.github.io/phy504/openmp-pi.html).

## Numerical integration

**Numerical integration** approximates an integral by combining contributions from small subintervals. A common integral for estimating $\pi$ is:

$$
\pi=\int_0^1\frac{4}{1+x^2}\,dx.
$$

### Methodology in the example

The code uses the **midpoint rule**, which approximates each subinterval's area by a rectangle whose height is evaluated at the midpoint.

1. Read `niter`, the number of subintervals, and set `h = 1.0 / (double) niter`.
2. Initialize `sum` to `0.0`.
3. For `i` from `1` through `niter`, compute the midpoint $x_i=h(i-0.5)$.
4. Add $4/(1+x_i^2)$ to `sum`.
5. Set `pi = h * sum` to multiply the accumulated heights by the subinterval width.

$$
\widehat{\pi}=h\sum_{i=1}^{N}\frac{4}{1+[h(i-0.5)]^2},
\qquad h=\frac{1}{N}.
$$

The computation loop is:

```cpp
  double h   = 1.0 / (double) niter;
  double sum = 0.0;
  for ( int i = 1; i <= niter; i++ ) {
    // compute integral from 0.0 to 1.0
    x = h * ( ( double )i - 0.5 );
    sum += ( 4.0 / ( 1.0 + x * x ) );
  }
  double pi = h * sum;
```

### Researched parallel methodology

Assign different subintervals to different workers. Each worker evaluates its assigned midpoints and accumulates a private partial sum. Combine the partial sums, then multiply by $h$.

An OpenMP implementation can use `reduction(+:sum)` to combine private sums. Another implementation accumulates privately and uses a `critical` region to add each completed partial sum to the shared total. Workers must finish before the final estimate uses that total.

Sources: [Tim Mattson's midpoint integration example](https://github.com/UoB-HPC/openmp-tutorial/blob/master/Solutions/pi_spmd_final.c) and [IIT Delhi's OpenMP integration examples](https://www.cse.iitd.ac.in/~dheerajb/OpenMP/Document/OpenMP_Examples.html).

$$
S(p)=\frac{1}{(1-f)+\frac{f}{p}},
\qquad f=\text{parallelizable fraction},\quad p=\text{number of processors}.
$$

## Reasons to use parallel computing

Parallel computing provides benefits beyond speedup:

- **CPU scalability** allows computation to use more CPUs.
- **Spatial memory scalability** allows data to be held across multiple machines. As data grows, one machine may no longer have enough memory to hold it all at once.

## Cache Usage — Performance Consideration 2

### Cache misses: The 3Cs

| Category | Cause |
| --- | --- |
| **Compulsory** | The first DRAM access due to a cache miss. |
| **Capacity** | Data replacement because the cache has reached its full capacity. |
| **Conflict** | Data replacement due to multiple hits to the same cache line. |

**Thrashing** involves repeatedly replacing cached entries and loading them again. It is related to cache replacement: repeated replacements reduce the benefit of keeping frequently used information in cache.

### Three types of cache memory

The hardware architecture separates caches for instructions, data, and address translations.

| Cache type | Details |
| --- | --- |
| **Instruction cache** | Only 32KB in Intel Haswell. Cached instructions are purged upon a branch. |
| **Data cache** | 32KB L1, 256KB L2, and 8MB L3 in Intel Haswell. |
| **Translation look-ahead buffer (TLB)** | Only 64 entries in both instruction and data pages. Flushed upon a process context switch. |

### Strategies for improving cache usage

**Temporal locality** means accessing the same information again within a short time. Keeping recently used data or instructions in cache makes repeated accesses faster. For example, a loop repeatedly uses the same instructions.

**Spatial locality** means accessing information near a location that was recently accessed. A cache line holds a block of nearby memory, so accessing consecutive array elements can reuse the same cache line.

1. Take advantage of spatial and temporal locality through loop unrolling and loop fusion.
2. Understand the three types of cache memory. Use loop unrolling, fewer branches in iterations, and multithreading rather than multi-processes.

## Cache Locality, Loops, and False Sharing

### Cache miss and false-sharing avoidance

Change the loop order so that `i` is the outer loop and `j` is the inner loop. For row-major arrays, varying `j` accesses consecutive elements within a row, improving spatial locality. Parallelizing the outer `i` loop assigns rows to workers rather than columns.

Before:

```cpp
#pragma omp parallel for
for ( int j = 0; j < n; j++ )
    for ( int i = 0; i < n; i++ )
        c[i][j] = a[i][j] * b[i][j];
```

After:

```cpp
// Changed: distribute rows among workers instead of columns.
#pragma omp parallel for
for ( int i = 0; i < n; i++ )
    // Changed: traverse adjacent elements within each row.
    // Benefit: reuse cache lines through spatial locality.
    for ( int j = 0; j < n; j++ )
        c[i][j] = a[i][j] * b[i][j];
```

**False sharing** occurs when different threads modify different locations in the same cache line, causing cache coherence traffic even though they are not modifying the same element. Assigning rows instead of adjacent columns helps avoid this pattern.

### Loop unrolling

**Loop unrolling** performs the work of multiple original iterations within one loop iteration. The example changes the increment from `i++` to `i += 2` and handles both `i` and `i + 1`, reducing loop-control operations and branches.

Before:

```cpp
#pragma omp parallel for
for ( int i = 1; i < n; i++ ) {
    a[i] = b[i] + 1;
    c[i] = a[i] + a[i - 1] + b[i - 1]
}
```

After:

```cpp
#pragma omp parallel for
// Changed: advance by two and handle two elements per iteration.
// Benefit: fewer loop-condition checks, increments, and branches.
for ( int i = 1; i < n; i += 2 ) {
    a[i] = b[i] + 1;
    c[i] = a[i] + a[i - 1] + b[i - 1]
    // Added: perform the work for the next element in the same body.
    a[i + 1] = b[i + 1] + 1;
    // Benefit: immediately reuse the a[i] value produced above.
    c[i + 1] = a[i + 1] + a[i] + b[i]
}
```

### Loop fusion

**Loop fusion** combines separate loops over the same index range. Here, `a[i]` is produced and then used to compute `c[i]` within the same iteration, taking advantage of temporal locality and reducing the number of parallel loop regions.

Before:

```cpp
#pragma omp parallel for
for ( int i = 0; i < n; i++ )
    a[i] = b[i] * 2;
#pragma omp parallel for
for ( int i = 0; i < n; i++ ) {
    x[i] = 2 * x[i];
    c[i] = a[i] + 2;
}
```

After:

```cpp
// Changed: one parallel loop replaces two parallel loops.
// Benefit: fewer loop-control and parallel-region overheads.
#pragma omp parallel for
for ( int i = 0; i < n; i++ ) {
    a[i] = b[i] * 2;
    x[i] = 2 * x[i];
    // Benefit: use a[i] immediately after producing it (temporal locality).
    c[i] = a[i] + 2;
}
```

### Loop fission

**Loop fission** splits a loop into separate loops for different computations. The example separates the calculation of `c[i]` from the update of `a[j][i]`, then makes `i` the inner loop of the array update so that it accesses consecutive elements within each row.

Before:

```cpp
#pragma omp parallel for
for ( int i = 0; i < n; i++ ) {
    c[i] = exp( i/n );
    for ( int j = 0; j < m; j++ )
        a[j][i] = a[j][i] + d[j] * e[i];
}
```

After:

```cpp
// Changed: calculate c[i] in a separate loop.
#pragma omp parallel for
for ( int i = 0; i < n; i++ )
    c[i] = exp( i/n );

// Changed: move j outside and i inside for the array update.
// Benefit: traverse a[j][i] along a row instead of down a column,
// reusing cache lines through spatial locality.
#pragma omp parallel for
for ( int j = 0; j < m; j++ )
    for ( int i = 0; i < n; i++ )
        a[j][i] = a[j][i] + d[j] * e[i];
```
