## Machine learning definition

Tom Mitchell's definition of machine learning uses three terms:

- **T** stands for task.
- **P** stands for performance measure.
- **E** stands for experience.

In paraphrase, a computer program learns from experience $E$ when that experience improves its performance on tasks $T$, with the improvement evaluated using performance measure $P$.

Source: Tom Mitchell, [*Machine Learning* (1997)](https://data.openml.dev/books/machine-learning-tom-mitchell.pdf).

In this context, **experience refers to the data**. As we have more data, performance should improve.

## Types of machine learning

**Reinforcement learning** is like a child learning through trial and error.

## Nearest Neighbor classification and learning approaches

The first algorithm covered is Nearest Neighbor classification. The lecture introduces two approaches: traditional programming and machine learning.

### Traditional approach

In the traditional approach, **we specify the procedure** that transforms the input into the desired output. This approach works well with *structured input*.

For example, suppose `A` contains 100 input values and we want the $k$th value in sorted order. We choose a sorting algorithm, use it to sort `A`, and return the $k$th value from the sorted list.

### Machine learning approach

In the machine learning approach, **we provide a large collection of paired inputs and outputs**. For handwritten number recognition, each example pairs an image with the number it represents.

The process has two stages:

1. The ML system uses the paired examples, $\{\text{input}, \text{output}\}_{i=1}^{N}$, as experience to develop an algorithm or system of rules for recognizing numbers.
2. We give that algorithm or system of rules a new input, and it produces a predicted output.

## Handwritten number recognition

### MNIST dataset

The first step in training such an algorithm is to obtain a dataset. For this number recognition task, we use the MNIST dataset.

Each MNIST image is $28 \times 28$ pixels. Each pixel has an integer value from 0 to 255.

### Vector representation

In machine learning, any input needs to be converted to a vector at some point. If we do not perform this conversion ourselves, the system will handle it somehow.

A vector can be a *row vector* or a *column vector*. If we have one form but need the other, we can use the *transpose* function to convert it.

$\mathbb{R}$ denotes the set of real numbers, and $\mathbb{R}^2$ denotes pairs of real numbers.

An MNIST image can be transformed into a vector in $\mathbb{R}^{784}$, since $28 \times 28 = 784$.

### Output labels

The number recognition algorithm has **labels** (outputs) ranging from 0 to 9.

### Fixed input and output spaces

For this problem, the input space $X$ and output space are fixed. Each image is represented by a vector in the input space $X = \mathbb{R}^{784}$. The supplied notation is:

$$

$$

## Defining Nearest Neighbor classification

### Training dataset

The training dataset contains 60000 images from MNIST, paired with their labels:

$$
(x^1, y^1), (x^2, y^2), \ldots, (x^{60000}, y^{60000}).
$$

These pairs are the experience.

**Test data must never be used to train the machine learning algorithm.**

### Remembering and testing

1. We do not need to train anything. We simply store the training examples in the `NN system` in memory and remember them.
2. To test the system, we feed a new input $x^{\text{new}}$ into the `NN system` to obtain a predicted output $\hat{y}^{\text{new}}$.

The `NN system` refers to the Nearest Neighbor classification system.

$$
x^{\text{new}} \longrightarrow \text{NN system} \longrightarrow \hat{y}^{\text{new}}.
$$

### Prediction rule

To predict the output for $x^{\text{new}}$, we compare its image vector with the image vectors in the training dataset. Nearness is measured by the distance between these vectors in the input space $X = \mathbb{R}^{784}$. We select the training example whose vector is closest to $x^{\text{new}}$ and use that example's label as the predicted output $\hat{y}^{\text{new}}$.

**How we calculate the distance between image vectors is key** to making the algorithm work and improving its performance.

### Distance measure

We use the **Euclidean distance** function to measure the distance between the test vector $x^{\text{new}}$ and each training vector $x^i$. Both vectors belong to $\mathbb{R}^{784}$, so the calculation includes all 784 dimensions:

$$
d(x^{\text{new}}, x^i)
= \left\|x^{\text{new}} - x^i\right\|_2
= \sqrt{\sum_{j=1}^{784}\left(x_j^{\text{new}} - x_j^i\right)^2}.
$$

Here, $j$ indexes the 784 components of each image vector.

### Formal testing procedure

Write image vectors with an underline, such as $\underline{x}^{\text{new}}$ and $\underline{x}^i$. The testing procedure compares the new vector with all 60000 training vectors, keeps track of the closest example found so far, and assigns its label to $y^{\text{new}}$.

```text
Test(x_new, y_new):
    nearest_distance = infinity
    final = undefined

    for i = 1 to 60000:
        current_distance = EuclideanDistance(x_new, x[i])

        if current_distance < nearest_distance:
            nearest_distance = current_distance
            final = i

    y_new = y[final]
```

Here, `x_new` represents $\underline{x}^{\text{new}}$ and `x[i]` represents $\underline{x}^i$. The variable `nearest_distance` stores the smallest distance found so far, and `final` stores the corresponding training example's index. Whenever a closer example is found, both variables are updated. After all comparisons, we assign its label `y[final]` to `y_new`, so $y^{\text{new}} = y^{\text{final}}$.

### Limitations of Euclidean distance and improvements

An image of the digit 1 can place the digit in the center or at a corner, and both images still correctly represent 1. **Euclidean distance fails in these cases** because the same digit occupies different positions in the images.

Two approaches improve how we compare images:

- **Tansent distance** accounts for small transformations of an image, such as shifts or rotations. It approximates how the image changes under these transformations, allowing images of the same digit to be considered similar despite small changes in position or orientation. This replaces the direct Euclidean comparison of the original image vectors. [Source](https://proceedings.neurips.cc/paper_files/paper/1992/file/26408ffa703a72e8ac0117e74ad46f33-Paper.pdf)
- **Shape context** represents a shape using the relative positions of its points. For each sampled point, a histogram summarizes where the other shape points lie relative to it. Comparing these descriptors helps match corresponding points between shapes, providing a way to compare digit shapes beyond their original pixel positions. [Source](https://papers.nips.cc/paper/2000/hash/c44799b04a1c72e3c8593a53e8000c78-Abstract.html)

### K-nearest neighbors

Another way to improve classification is to use **K-nearest neighbors**: select the $K$ closest training examples instead of just one, then use a **majority vote** among their labels to determine the predicted output.

$K$ should be odd to help determine the majority.

**A larger $K$ does not necessarily produce better results.** We need to choose $K$ carefully.

### Choosing K with cross-validation

$K$ is the number of neighbors used for prediction. **Cross-validation** is a method for evaluating candidate choices of $K$ using different training and validation splits.

For each candidate $K$, we fit the classifier on the training portion and evaluate it on the held-out validation portion. We repeat this across the splits, compare the average validation accuracy, and choose $K$ based on those results. The test data remain separate for the final evaluation.

In *k-fold cross-validation*, the data are divided into $k$ folds, with each fold used for validation in turn. **The number of folds and the number of neighbors are separate choices**, even though both may be called $k$.

Source: [scikit-learn cross-validation guide](https://scikit-learn.org/stable/modules/cross_validation.html).

## Parametric and non-parametric approaches

Consider a simple case with only two labels in the input space. A **decision boundary** splits the space into regions associated with the two labels. Each point is assigned the label of its nearest training example.

In the *non-parametric* case, the decision boundary can become more complex as we add more data. In the *parametric* case, adding more data does not increase the complexity of the decision boundary.

| Approach | Effect of adding more data on decision boundary complexity |
| --- | --- |
| Non-parametric | The boundary can become more complex. |
| Parametric | The boundary's complexity does not increase. |
